## 二、软件功能与技术特点说明

### 2.1 软件概述

本软件是一个基于大语言模型与检索增强生成（Retrieval-Augmented Generation, RAG）技术的智能知识问答系统。用户通过 Web 浏览器登录系统后，可上传 PDF、DOCX、Markdown、TXT 等格式的领域文档，系统自动完成文档解析、文本切分与向量化入库，构建个人专属知识库。用户基于知识库提问时，系统先通过"向量语义检索 + BM25 关键词检索"的混合检索策略召回相关文本片段，再交由大语言模型组织生成答案，答案中标注引用编号，可点击查看原文出处，有效解决了通用大模型在垂直领域知识不足与"幻觉"问题。

### 2.2 主要功能

| 功能模块 | 功能描述 |
|----------|----------|
| 用户认证 | 注册、登录，基于 JWT 的身份鉴权，用户数据相互隔离 |
| 知识库管理 | 新建、编辑、删除知识库，支持多知识库并行 |
| 文档管理 | 上传 PDF/DOCX/MD/TXT 文档，自动解析入库，展示解析状态，支持删除与失败重试 |
| 文档解析 | 支持 PDF 分页提取、DOCX 段落与标题识别、文本文件 GBK/UTF-8 自动识别 |
| 文本切分 | 基于段落/句子优先级的递归字符切分，支持重叠窗口 |
| 向量化 | 支持云端 Embedding API 与本地 BGE 模型两种向量化方式 |
| 混合检索 | 向量余弦相似度检索与 BM25 关键词检索，通过 RRF 算法融合排序 |
| 智能问答 | 基于检索上下文的大模型问答，支持 SSE 流式逐字输出 |
| 引用溯源 | 回答自动标注引用编号，展示相似度、来源文档、页码与原文片段 |
| 会话管理 | 多会话记录，历史消息查看与删除，会话自动命名 |
| 数据统计 | 知识库、文档、文本块、会话、消息数量的统计与可视化 |

### 2.3 技术特点

1. 采用"检索增强生成（RAG）"框架，将检索与生成解耦，知识库可动态更新，无需重新训练模型；
2. 设计"向量语义检索 + BM25 关键词检索 + RRF 排名融合"的混合检索策略，兼顾语义理解与精确匹配；
3. 基于 HTTP 流式传输（SSE）实现大模型回答的逐字输出，提升交互体验；
4. 使用嵌入式向量数据库（ChromaDB）与 SQLite，系统部署简单，无需额外服务；
5. 前后端分离架构，前端为零依赖原生 Web 页面，可离线运行。

## 四、软件技术架构

### 4.1 总体架构

系统采用前后端分离的三层架构：

- **表现层**：原生 HTML/CSS/JavaScript 实现的 Web 界面，包含用户认证、智能问答、知识库管理、数据统计四个页面；
- **应用层**：基于 Python FastAPI 框架的 RESTful API 服务，包含认证、知识库管理、会话管理、统计四个接口模块；
- **核心服务层**：自主实现的 RAG 管线，包含文档解析、文本切分、向量化、混合检索、Prompt 组装、大模型生成六个组件；
- **数据层**：SQLite（元数据）、ChromaDB（向量数据）、文件系统（文档原件）。

### 4.2 核心处理流程

**文档入库流程**：上传文档 → 格式校验 → 解析（PDF/DOCX/MD/TXT）→ 递归字符切分 → 批量向量化 → 写入向量库与元数据库 → 更新统计。

**问答流程**：接收提问 → 向量检索 + BM25 检索 → RRF 融合排序取 Top-K → 组装带引用编号的 Prompt → 大模型流式生成 → 返回回答与引用来源 → 保存会话记录。

## 五、数据库设计说明

系统使用 SQLite 关系数据库存储元数据，共 6 张数据表：

| 表名 | 用途 | 关键字段 |
|------|------|----------|
| users | 用户信息 | id、username、password_hash、created_at |
| knowledge_bases | 知识库 | id、user_id、name、description、doc_count、chunk_count |
| documents | 文档 | id、kb_id、filename、file_path、file_type、file_size、status、chunk_count、error_msg |
| chunks | 文本块 | id、kb_id、doc_id、seq、content、meta(JSON)、vector_id |
| conversations | 会话 | id、user_id、kb_id、title、created_at、updated_at |
| messages | 消息 | id、conversation_id、role、content、sources(JSON)、tokens |

向量数据使用 ChromaDB 持久化存储，按知识库建立集合，采用余弦距离度量；每条向量通过 vector_id 与 SQLite 中的 chunks 表关联，保证两份存储的一致性。

## 六、软件操作说明

> 以下每步均需**附系统运行截图**（截图要求见文末）。

### 6.1 系统部署

1. 安装 Python 3.9+，执行 `pip install -r requirements.txt` 安装依赖；
2. 将 `.env.example` 复制为 `.env`，配置大模型 API 密钥；
3. 执行 `python -m uvicorn app.main:app --host 0.0.0.0 --port 8000` 启动服务；
4. 浏览器访问 `http://127.0.0.1:8000`。

### 6.2 用户注册与登录

1. 打开系统首页，进入登录界面；
2. 点击"注册"标签，输入用户名与密码完成注册；
3. 使用注册账号登录进入主界面。

### 6.3 新建知识库与上传文档

1. 点击顶部导航"知识库管理"；
2. 点击"新建知识库"，输入名称与描述；
3. 在知识库卡片中点击"上传文档"，选择 PDF/DOCX/MD/TXT 文件；
4. 等待系统解析完成，文档状态显示"可用"，并显示切分后的文本块数量。

### 6.4 智能问答

1. 进入"智能问答"页面，在左侧下拉框选择目标知识库；
2. 输入问题并发送，系统流式输出回答；
3. 回答中的 [n] 标记与"来源"标签可点击，弹出原文片段与相似度信息。

### 6.5 会话管理

1. 左侧"会话记录"展示历史会话，点击可查看完整对话；
2. 点击"新对话"创建新会话；点击 × 删除会话。

### 6.6 数据统计

点击"数据统计"查看知识库、文档、文本块、会话、消息数量统计及知识库文档分布图。

中国版权保护中心要求提交源程序**前、后各 30 页**（共 60 页），每页 50 行（不足 60 页则全部提交）：

| 要求项 | 说明 |
|--------|------|
| 提交范围 | 源程序前 30 页 + 后 30 页 |
| 页格式 | A4，每页约 50 行代码，行号连续 |
| 内容要求 | 应包含体现软件核心功能的代码（如 RAG 检索、问答接口、文档处理等） |
| 格式要求 | 纯文本或程序语言代码，不得出现作者信息之外的公司信息 |

**本项目推荐提交的源程序文件**（覆盖核心功能）：

```
app/rag/pipeline.py        # RAG 主流程编排（核心）
app/rag/retriever.py       # 混合检索器（向量+BM25+RRF）
app/rag/embedder.py        # 向量化模块
app/rag/splitter.py        # 文本切分
app/rag/generator.py       # LLM 生成与流式输出
app/rag/prompts.py         # Prompt 工程
app/rag/loader.py          # 文档解析
app/api/chat.py            # 对话接口
app/api/kb.py              # 知识库接口
app/main.py                # 应用入口
```

**操作指引**：将上述文件按顺序拼接导出为 60 页（每页 50 行）的文本，可直接使用脚本工具自动排版生成。

## 八、登记申请流程指南

1. **注册账号**：在中国版权保护中心官网注册个人账号（或通过学校代办）；
2. **在线填报**：进入"计算机软件著作权登记"，填写软件基本信息（对应本文档第一部分）；
3. **上传材料**：
   - 源程序文档（前后各 30 页，对应第七部分）；
   - 软件文档（本模板第二~六部分 + 运行截图，建议整理为《软件说明书》20 页以上）；
   - 身份证明（个人：身份证正反面；法人：营业执照等）；
4. **提交核验**：部分省份需现场/在线核验；
5. **缴费**：普通登记一般免费（个人申请）；加急渠道收费；
6. **审查发证**：普通审查约 30~60 个工作日，加急最快 1~3 个工作日；
7. **电子证书**：通过后可在官网下载电子版证书（效力等同纸质）。
